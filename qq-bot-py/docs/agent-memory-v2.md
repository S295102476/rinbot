# 新版长期记忆与群友评价

新版记忆继续使用现有 MySQL 和 MinIO，不需要部署向量数据库。默认不开启；先在开发群启用，观察队列和召回内容后逐群扩大。

```yaml
agent:
  memory_v2:
    enabled: true
    groups: [987654321]  # 替换为测试群；空列表表示所有已启用 Agent 的群
    embeddings_enabled: false
  model_routes:
    memory:
      provider: primary
      protocol: openai
    embedding:
      enabled: false
      provider: google
      protocol: embedding
      model: gemini-embedding-2
```

接口地址与密钥沿用对应供应商配置；控制台用途路由显示生效值。聊天整理走 `memory`，默认复用 `ai` 的接口和模型，不根据模型名称猜协议。向量走 `embedding`；配置 Google 凭据后同时开启该路由与 `embeddings_enabled`。未配置向量密钥、配额耗尽或服务故障时继续使用人物与中文关键词检索。

## 可靠写入与内容边界

每条有效群消息写入持久输入表，同时建立群整理任务。即使机器人处于仅 @ 回复模式，也能记录开启学习的用户发言。原来的 500 条热窗口不再控制长期来源保留。

每 60 秒检查任务，累计 30 条或等待 5 分钟后整理。每批最多 100 条、约 28000 字符；任务通过租约恢复重启中断，失败指数退避。模型生成的事实与任务检查点在同一事务提交。归档、检索和模型错误均不在日志写出供应商返回体或密钥。

数据库暂时不可用时，预处理入口将消息写入私有本地 `data/agent-memory-inbox`。Linux 目录权限为 `0700`、文件为 `0600`，先写临时文件并同步磁盘，再原子替换为按群与消息 ID 计算的文件名。后台恢复后仍通过相同去重、隐私与遗忘时间检查入库，成功提交后才删除本地文件；不会绕过数据库直接送给模型。

本地收件箱最多 5000 个文件或 128 MiB，达到 80% 显示提醒；容量耗尽或磁盘不可写会报错并保留已有文件，不通过覆盖旧消息腾空间。数据库与本地磁盘同时不可用时无法保证新消息持久化，需要按控制台错误检查容量和权限。有效暂存原文最多保留 90 天；格式异常、软链接或路径不符合规则的文件不处理，保留供管理员检查。控制台整理状态包含 `spool.pending`、容量和类型化错误，即使数据库离线也能查询本地积压。迁移机器人时应一并保留此私有目录。

每条事实必须绑定本人消息；事件、风格、群梗保存来源 ID 和摘录。风格至少需要 20 条消息并跨 3 个自然日。跨群事实仅接受本人第一人称明确给出的稳定身份或偏好；旧版全局事实迁移到原群，不推测其全局适用性。相同事实主题更新时替代旧值，人工保护内容优先。

检索先按群和人物过滤，再结合关键词与语义分数。当前发言人、真实 @ 对象和引用对象由宿主传入。仅对明确允许的群使用群梗；相关群梗进入上下文时保守计费：同梗每天一次、每群每天四次、间隔十五分钟。没有被模型实际使用的推荐也会占用一次，避免反复推荐。严肃场景和关闭主动接话时可禁止群梗召回。

## 用户控制和评价卡

| 指令 | 作用 |
|---|---|
| `#我的记忆` | 查看本群与明确跨群的个人记忆及编号 |
| `#纠正记忆 编号 内容` | 本人纠正并保护记忆 |
| `#删除记忆 编号` | 删除个人记忆及相关派生条目，阻止来源重学 |
| `#忘记我` | 停止本群学习、立即停止召回、后台清理归档 |
| `#关闭学习` / `#开启学习` | 控制本群新消息学习 |
| `#关闭风格学习` / `#开启风格学习` | 控制风格建档与使用 |
| `#关闭被评价` / `#开启被评价` | 控制评价卡 |
| `#评价我` / `#评价 @群友` | 生成有消息依据的评价卡 |

评价只使用本群最近 30 天、至少 10 条消息且跨 2 天的观察，生成 4–6 项特点和总结。同一目标一小时内复用结果。模型伪造消息引用时拒绝生成；卡片只插入转义后的文本，不加载外部资源。评价不写回人物事实。对其他人的评价必须有当前消息中的真实 @。删除后重新开启学习只允许新消息形成记忆，旧来源仍被删除标记阻止。

删除单条记忆时，为确保旧归档不再包含来源，后台会清理该作者在相关群的归档对象；其他仍有效的结构化记忆保留。控制台管理员可以查看来源、修订记录、观察队列和撤回学习。

## 归档与向量预算

使用专门的私有 `agent-memory` 存储桶，禁止公共读取。已整理、超过 30 天的原文按群、作者和日期压缩归档，上传后下载并校验 SHA-256，成功才删除数据库镜像。原文从发言时间计算保留 90 天；有效结构化记忆继续保留必要证据摘录。

归档上限 5 GiB，达到 80% 在控制台提醒。满额或存储不可用时保留数据库原文，不能通过丢弃输入释放空间。用户删除归档和过期清理均由后台重试。此容量监控针对这个专用存储桶；不要手工向其中写入无关文件。

每条有效结构化记忆独立生成 768 维向量，记录模型、版本和内容指纹。首次索引预留上限 100 万输入 token，日常预留上限 25 万；采用 UTF-8 字节数加固定开销保守预留，因此计数可能大于实际用量。调用前预留，失败不退还，防止失败循环超额。查询缓存按群隔离、五分钟过期；人格和原始聊天不批量向量化。

## 迁移与回退

先保存数据库备份，再运行：

```bash
python tools/migrate_agent_memory_v2.py         # 默认只显示预计数量
python tools/migrate_agent_memory_v2.py --apply
```

迁移是新增记录，不覆盖旧事实、人设、好感或人工保护记录。无法确认来源的旧全局事实降为原群事实，短记忆作为 `candidate` 保存、置信度 0.3，不能直接参与召回。现有人工编辑的有效记录保留保护标记，已删除或停用记录跳过；重复迁移按指纹去重。迁移不会调用模型，也不会自动重新构造已经丢失的原文。

每次开启前检查数据库表权限和专用存储桶权限。关闭 `memory_v2.enabled` 后基础聊天与原指令继续工作；新版记录保留供检查。旧版召回也检查新版隐私与删除台账；无法追踪来源的旧滚动摘要不再注入。恢复数据库备份时必须保留后续删除台账，避免重新暴露已删除的内容。

离线验证：`python -m pytest tests/test_agent_memory_v2.py -q`。测试使用临时 SQLite、虚拟对象存储和假模型，不连接个人数据库或真实模型。
