# 人格交流偏好与关系边界

本次优化针对凛与伊什塔尔的日常语气，并统一三个角色的恋人关系门槛。模型保持既有人格，通过来源明确的交流偏好调整表达，不训练模型权重。

## 温柔而保留人格

平常仍可以轻微傲娇、吐槽和接梗。群友明确说“不喜欢被呛”“不要总损我”“温柔一点”时，当次先认可并收敛，避免反嘲、贴敏感标签或因为合理表达边界扣好感。

在开启 Memory V2 的群，后台将本人明确的语气和关心偏好分别保存为 `interaction_tone`、`interaction_care` 事实。明确偏好不需要等待推测风格所需的 20 条消息、3 天观察：低活跃群通常约 5 分钟后开始整理，也可在控制台「整理任务」触发重试。当前回应立即依据当前消息与近期上下文调整；长期保存仍以后台整理成功为准，失败时持久队列继续重试。

偏好按真实作者和来源群保存。用户点名某个人格时，记忆正文保留该适用范围，不把凛的偏好自动推广给其他人格。召回时即使已换话题，也优先提供短偏好区块，最多 1,000 字符，包含在原有记忆预算内，并保留其他事实空间。人工保护、更新替换、学习关闭、来源删除与忘记操作继续生效。

公开配置默认关闭 Memory V2；已有部署继续使用自己配置的测试群范围，不会自动扩大到所有群。未开启 V2 的群也会立即遵守当前表达和人格规则，但不使用新的偏好优先召回链路。

## 时间与关心

时间只帮助判断消息时序，不是每次聊天的主题。深夜讨论游戏、代码或图片时不自动催睡。用户主动提到困倦、熬夜或身体不适时，可以简短关心一两句；已经提醒、用户没接或明确拒绝时不重复。

“早点睡”“困不困”“睡了没有”之类日常关心不会创建定时追问。旧的待执行催睡追问在检查时过期，不再调用模型或发送消息。设备睡眠模式、失眠持续时间、代码编译和游戏等具体问题仍可正常跟进。

## 好感度与亲密表达

- 85 至未满 100：高度信任的朋友，仍保持友情边界。
- 该人格真实好感恰为 100：才允许在双方当下愿意时适当回应恋人式亲密。
- 99.9、99.99 等不能因为排行榜显示取整而放宽门槛。注入模型的上下文会明确标记真实满好感是否达成；读取的是该人格自身的存储分数。
- 用户自报满分、历史暧昧称呼、其他人格的好感或专属档案不能绕过该门槛。缺少可靠关系状态时默认没有解锁。
- 未满分时不轻易回应亲亲、索吻或默认接受暧昧动作；可以温和拒绝、轻微害羞或转回话题。满分也不等于无条件同意，不扩写括号动作。

艾蕾同步关系门槛与下述识图规则，保持原有语气与性格。

## 识图语境

有引用图片时，以该引用图为当前回答对象，不混入无关的新图。没有引用图片时，默认使用本次消息的最后一张图；紧接着询问“这张图是谁”等问题时，可以使用当前话题最近的一张群图。普通闲聊不自动附带历史图片或用户头像。

旧图只在明确回看、提到“上一张”“之前那张”或要求对比时参与；明确讨论“这几张图”时才提供多图，并继续受现有图片数量预算限制。图源标签保留发送者、消息来源和顺序，避免将其他人的图片、引用图和头像混淆。

选定的图片下载失败时说明无法读取，不改拿另一张旧图代替。三个角色的人格提示、Agent 主路径及旧聊天路径使用相同的优先原则。

## 当前上下文预算

Agent 主群聊读取最近最多 60 条消息、12,000 字符；这些是本群近期消息，并非每个用户各自 60 条。

Memory V2 每轮召回最多 5,000 字符，包含相关用户事实、风格、群内事件和群梗；再加最多 1,000 字符关系状态，合计约 6,000。不是给每个用户单独分配 6,000 字符，也没有固定“每次必取几条”的条数。发言人、真实 @ 对象和引用对象参与检索，事实与风格不会混用其他用户。

人格、规则、工具说明、当前请求、历史和工具结果的总文本预算为 32,000 字符。只保留相关内容，预算没有随本次优化增加。上述是本地代码和配置的输入上限；服务器数据库当前每个用户实际有多少条记忆，需要读取生产库才能确认。

## 验证建议

1. 对凛明确表达不喜欢被损，确认本轮收敛；待后台整理完成，换话题或重启后再确认。
2. 用户引用其他人的抱怨，不应被记录成引用者自己的偏好；其他群与群友不受影响。
3. 深夜询问游戏或代码应直接回应问题；一次关心后不建立定时催睡链路。
4. 99.99 保持友情距离；真实 100 在明确愿意时可以适当亲密，各人格分数不能混用。
5. 在控制台修改、保护或删除偏好后，后台不会覆盖受保护版本或恢复已删除来源。
6. 连续发送两张不同话题的图，默认只聊最新图；引用第一张时回到第一张；明确要求对比时才结合两张。普通文字闲聊不延续旧图评价，无法读取引用图时不改认最新图。

本地自动测试使用合成消息、SQLite 与模拟供应商，没有对生产 QQ、数据库或模型接口进行真实互动验收。
