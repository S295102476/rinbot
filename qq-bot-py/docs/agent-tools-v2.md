# 自然语言小游戏与 GPT 专家

自然语言游戏调用与原有 `#小游戏` 指令共用游戏服务、存储、规则、图片和本地引擎，不会创建假的 QQ 消息。保留原来的游戏指令；直接坐标和答题指令通常响应更快。

## 测试群开启

合并到现有配置，不要复制私人凭据：

```yaml
agent:
  game_tools:
    enabled: true
    groups: [987654321]  # 替换为测试群；空列表表示所有已启用 Agent 且允许小游戏的群
  expert:
    enabled: true
    groups: [987654321]
    daily_limit: 20
  model_routes:
    expert:
      enabled: true
      provider: openai_responses
      protocol: responses
      # 模型沿用 ai.openai_responses.model，也可明确填写接口支持的模型。
      timeout: 180
      max_output_tokens: 6000
      concurrency: 2
```

GPT 沿用 `ai.openai_responses` 的接口配置和环境变量密钥。公开部署默认关闭专家；填写接口地址、密钥与模型后，同时开启 `expert.enabled` 和 `model_routes.expert.enabled`，并启用上面的测试群配置。模型名称需由配置的接口实际支持。控制台用途路由可以独立关闭专家、设置模型和每日额度；群范围来自 `expert.groups`，兼容旧字段 `expert.allowed_groups`。专家每群每天默认最多 20 次，每批群消息最多一次；Redis 故障时暂停专家调用，基础聊天继续工作。按北京时间日期计数，失败请求也占用额度，避免失败循环反复产生费用。

## 游戏请求

| 场景 | 示例 |
|---|---|
| 开局 | `凛，来一局五子棋`、`艾蕾，玩猜数字`、`来一局成语填空 抢答` |
| 邀请群友 | `来一局五子棋 @群友`，必须使用真正的 QQ @ |
| 指定参数 | `来一局五子棋 认真 后手`、`来一局围棋 双人 13路` |
| 查看 | `看看棋盘`、`查看题目` |
| 下棋 | `下 H8`、`走棋 炮二平五` |
| 控制 | `悔棋`、`同意悔棋`、`我认输了`、`结束这局`、`我加入` |
| 答题 | `猜 1234`、`作答 春暖花开`、`跳过这题` |
| 围棋结算 | `停一手`、`标死 D4`、`取消死子 D4`、`确认数目`、`继续对局` |

支持五子棋、井字棋、象棋、围棋、成语填空与猜数字。默认五子棋人机娱乐难度、用户先手；答题默认单人。象棋、围棋人机与五子棋认真难度仍需要现有本地引擎，缺少引擎时明确提示，不会偷偷切换难度。

模型只负责把明确请求映射为工具。发起人和群号固定来自真实消息，邀请对象固定来自真正的 @，规则、落子和判题由程序完成。自然语言是刻意收窄的请求入口，普通讨论、否定和假设不会触发游戏。复杂说法不能识别时可以改用上述示例或原有指令。

调用模型前记录棋局版本；等待期间棋局变化时，操作被拒绝并提示重新查看。已有对局时，新的开局请求展示当前游戏，不替换或结束旧局。同一真实消息重复投递不会重复落子。游戏已经发送卡片或安排机器人落子后，本轮 Agent 结束，不再多调用模型复述。

仅 @ 群也允许这些明确游戏请求进入，仍受 Agent 群范围、总配额和游戏开关约束，不开启普通主动聊天。关闭 `game_tools.enabled` 可以退回原有手动游戏指令。

## 专家职责

明确点名 GPT 或主 Agent 判断为复杂任务时，可调用 `ask_expert`。专家只收到当前问题和允许的必要背景，不接收开发历史、生产目录、事件对象或工具权限；结果由当前人格组织回复。普通任务总时限 120 秒，委派 GPT 后总时限 240 秒，单个模型请求仍受用途路由限制，排队最多 15 秒。

Responses 与 Chat Completions 的原生函数调用结果会转换为相同的宿主工具格式，执行前仍经过作用域、参数、真实身份和权限检查。接口未声明支持的能力不会自动启用。

开发能力只存在于管理员的独立开发任务，详见[开发任务说明](developer-tasks.md)。群友评价、查看和删除个人记忆详见[长期记忆说明](agent-memory-v2.md)。
