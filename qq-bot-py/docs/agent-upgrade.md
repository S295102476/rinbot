# RinBot Agent 升级与验收

本次升级在现有 NoneBot、MySQL、Redis、MinIO 上实现，没有增加完整 Agent 框架或训练模型。人格继续来自原有配置；群友风格通过有来源的记忆改善表达，不自动模仿某个人。

入口文档：[完整配置示例](agent-upgrade.example.yaml) · [长期记忆与评价](agent-memory-v2.md) · [小游戏与专家](agent-tools-v2.md) · [开发任务](developer-tasks.md)。

## 模型和任务边界

| 用途 | 默认模型 | 单次上限 |
|---|---|---|
| 主聊天与识图 | `primary`，沿用 `ai` 配置的接口与模型；识图需模型支持 | 90 秒 |
| 摘要、人物、风格、群梗、评价卡 | `primary`，默认沿用同一已配置模型 | 180 秒 |
| 回复情绪 | `primary`，可单独指定更快的模型 | 15 秒 |
| 批量表情分类 | `primary`，需要图文模型 | 30 秒 |
| 语义向量 | Google `gemini-embedding-2`，768 维，默认关闭 | 30 秒 |
| GPT 群聊专家 | 配置的 Responses 接口与模型，默认关闭 | 180 秒 |
| GPT 开发任务 | 同接口、独立职责与上下文，默认关闭 | 每轮 180 秒 |

程序按显式协议发送，不从模型名称判断能力。需要使用 AG 时，先配置 `ai.antigravity`，再把对应用途设为 `provider: antigravity`、`protocol: openai` 并填写实际支持的模型。已有部署的明确路由和控制台覆盖继续保留。表情入库审核支持豆包描述→DeepSeek 判断；开启审核前配置对应凭据与收集规则，审核失败不入库。

控制台「用途路由」和 `#切换模型` 使用同一服务，后者只改主聊天。旧控制台全局模型在启动时只迁移到主聊天；之后摘要、情绪和专家互不跟随。界面显示有效模型、来源、超时、输出与并发限制，不返回密钥或私人接口地址。旧 Agent 设置中的模型字段仍兼容，其他用途请在新页面修改。

普通聊天工具任务总时限 120 秒，首次委派专家可延长至 240 秒；排队最长 15 秒。小游戏或评价工具已发图后停止本轮，不再要求模型复述。开发任务最多 8 轮、总执行 15 分钟，审批另有 24 小时有效期。

最近原文最多 60 条、12000 字符，长期召回最多 6000 字符，文字总上下文上限 32000。规则和当前请求优先，其次是工具结果和相关历史；图片另受原有数量与缩略图限制。旧的跨群管理员原文不再额外注入。

## 首次上线

先在已有开发群验证，再调整各能力的 `groups`。现有私有配置不会被脚本自动重写；将示例内容合并到配置，保留真实管理员、数据库与接口凭据。空群列表会扩大到已启用的 Agent 群，不适合第一次试运行。

1. 在服务器保存数据库和本地配置。可用现有备份方式，或安装 MySQL 客户端后运行：

   ```sh
   python tools/agent_upgrade_backup.py --destination ../private-backups/rinbot-agent-before
   ```

   目录必须在项目外且为空。内含私有配置，不上传 GitHub。确认 `database.sql.gz` 完整及 `manifest.json` 哈希；恢复演练应使用隔离数据库。

2. 合并配置、上传源码、构建控制台：`cd console && npm ci && npm run build`。沿用项目已有依赖；运行评价卡需要已安装的 Playwright Chromium 和中文字体。

3. 运行 `python tools/migrate_agent_memory_v2.py` 查看旧记忆预计数量；备份确认后使用 `--apply` 新增结构化记录。脚本不覆盖旧表，不调用模型，重复执行按指纹去重。旧短记忆只成为低可信候选，不直接进入聊天。已丢失的聊天原文不会补造。

4. 管理员安排服务重启。启动钩子创建新增表、载入用途路由、恢复记忆与开发检查点。新版记忆开启后才启动整理与向量后台调用；初次旧记忆索引使用独立预算。

5. 在控制台检查用途路由、整理任务和向量预算。使用测试群完成下面的演示；不要仅以 HTTP 端口可访问作为功能验收。

6. 开发功能还需构建 `tools/Dockerfile.developer-checks`。Docker 不可用或检查失败时不能批准应用；不会在生产宿主直接执行生成代码。

MySQL 新增 `agent_v2_*`、`agent_developer_tasks` 表；路由覆盖沿用 `console_settings`。现有多个插件的启动建表统一串行执行，避免首次建表竞态。MinIO 使用私有 `agent-memory` 桶，5 GiB 上限、80% 提醒；先无需扩容服务器。已整理原文 30 天后压缩归档，到发言后 90 天清理。归档校验失败保留数据库输入。

数据库短暂不可用时，入站消息原子写入私有 `data/agent-memory-inbox`，数据库恢复后经隐私检查和去重再重放。暂存最多 5000 文件、128 MiB，保留最多 90 天；控制台显示积压与错误。数据库和本地磁盘同时不可用、或暂存已满时无法保证保存新消息，需要管理员恢复存储。

## 固定演示与观察

使用演示账号和群号，记录下列相同输入在升级前后的结果。机器可读案例见 [演示集](../tests/fixtures/agent_upgrade_scenarios.json)。

| 场景 | 验收重点 |
|---|---|
| 本人先说喜欢某游戏，隔天换一种问法询问 | 召回本人相关旧事，有来源，没命中时不编造 |
| @ 另一名群友；两个同名用户 | 依据 QQ 身份召回，不能把发送者事实当目标事实 |
| 两个群分别讨论同一个梗 | 群梗与关系不跨群；主动调用次数受限 |
| 20 条消息跨 3 天后继续交流 | 风格档案需多条跨日证据，保持机器人原人格 |
| 纠正旧偏好、删除来源、关闭学习后重启 | 人工内容优先、删除不复活、归档和向量随后清理 |
| `#评价我`、`#评价 @目标` | 样本不足说明原因；关闭被评价后禁止生成 |
| 来一局五子棋、下 H8、看棋盘、悔棋、认输 | 复用原游戏规则；重复、非玩家和过期版本拒绝 |
| 六种游戏、缺少外部引擎 | 能力说明准确、基础难度正常或明确提示缺引擎 |
| 点名 GPT，随后再次要求委派 | 单任务只请求一次；保留当前人格组织答案 |
| 群聊要求读取 config、提出开发补丁 | 群聊无开发权限；私聊/控制台任务等待同管理员审批 |
| 开发检查失败、审批前改动源码、重启恢复 | 不应用失败检查或失效审批；恢复有检查点和记录 |

观察控制台请求记录的输入字符、耗时和工具成功/失败；长期记忆页面查看每次召回对应来源和修订，整理任务查看积压及预算。人工记录演示集命中数、错误操作数、主动玩梗是否合适及纠正次数。未进行真实 QQ 会话或付费模型调用时，不把离线测试结果当成真实召回质量结论。

## 测试和回退

```sh
python -m pytest tests -q
cd console
npm run build
npm test
```

新增关键测试使用假模型、临时 SQLite、对象存储替身和模拟 QQ 事件，覆盖失败、重复、权限、并发、审阅与隐私。浏览器流程使用 API 替身；真实 MySQL/Redis/MinIO、模型中转、QQ 回复与真实 Docker 检查还要在开发群完成联调。

回退先关闭 `memory_v2.enabled`、`game_tools.enabled`、`expert.enabled` 或对应用途开关。基础聊天与原游戏指令保留，新增表不要删除。隐私过滤在旧召回路径仍生效，避免切回旧记忆后重新暴露已删除内容。上线前数据库备份用于灾难恢复；恢复较旧备份时必须同时恢复后续删除记录。开发补丁应用和回滚均由管理员审批，不自动重启或发布。
