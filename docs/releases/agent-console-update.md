# Agent、控制台与单工作区更新

本轮将正在使用的 Agent、控制台、人设和表情优化合并进同一个源码仓库。今后从这一份工作区开发、测试和提交；Git 忽略私人配置、SFTP、数据库、日志和迁移包，不再要求同时修改公开目录和私人目录。

## 新增能力

- **按用途模型路由**：主聊天、摘要、情绪、表情分类、向量、GPT 专家和开发任务分别管理，控制台展示有效模型与来源。公开模板使用部署者自己的 Chat Completions 主接口；不需要维护者的中转地址。
- **长期记忆 V2**：消息持久队列、重启恢复、带来源的事实与事件、群内风格和群梗、关键词与可选向量召回、私有归档和用户删除控制。先在测试群启用，再扩大范围。
- **群友评价卡**：使用本群有效观察生成特点与总结，样本不足不编造；用户可以关闭被评价。
- **自然语言小游戏**：六种游戏通过真实消息发起、查看和操作，检查玩家身份、棋局版本与合法操作；原指令保留。
- **可选 GPT 协作**：群聊专家只有问答上下文；管理员开发任务使用隔离源码副本、完整差异、容器检查、审批和回滚记录，不自动重启或发布。
- **控制台外观与布局**：修复长期记忆、整理和开发任务的内容溢出；增加三种星空背景、自定义本地壁纸、主题颜色、明暗模式与毛玻璃设置。
- **人格与识图**：凛和伊什塔尔尊重明确的交流偏好，减少重复作息提醒；真实好感度达到 100 才允许恋人阶段。引用图片优先，没有引用时默认最新一张，明确回看或对比才读取旧图。
- **表情库**：符合情绪与启用状态的全池等概率随机选图，保留近期去重和冷却；QQ 发送确认成功后计数。修复分类同步和停用状态覆盖，自定义收集规则可以用文件管理。

## 新部署

按根目录 [README](../../README.md) 和[配置参考](../configuration.md)初始化四个服务。只配置自己的主模型接口、管理员、允许群与控制台密码，即可先运行基础聊天和控制台。识图与图文分类取决于主模型的视觉能力。

公开模板中新版长期记忆、Google 向量、GPT 专家和开发任务默认关闭；它们需要单独开启和配置。小游戏自然语言工具默认开启。外部棋类引擎、绘图、Pixiv、Core 和 GBVSR 数据仍按需安装。

## 已有用户升级

1. 一起备份配置、数据库、运行数据及私有资源；新表不能替代可验证的备份。
2. 更新源码及控制台构建结果，保留自己的 `config.yaml`、`.env`、SFTP 和私有人设。不要用公开模板覆盖现有配置。
3. 从[Agent 升级说明](../../qq-bot-py/docs/agent-upgrade.md)合并需要的字段；开启新版记忆前先设置自己的测试群。已有独立 AG high/low 分工继续保留，不必改为公共模板的共享接口。
4. 迁移旧记忆先运行 `python tools/migrate_agent_memory_v2.py` 预览，确认备份后再 `--apply`。迁移新增记录、保留人工保护和删除标记，不从丢失原文补造经历。
5. 重启后核对控制台路由、整理任务、实际 QQ 回复、图片和数据持久性。开发任务启用前另构建隔离检查镜像。

## 限制与验证范围

旧表情累计次数可能包含历史预选记录，不会自动清零。新收集规则只影响新图，不自动清理旧库；入库审核仍需豆包描述与 DeepSeek 判断。控制台主题和自定义壁纸保存在当前浏览器，换电脑后可重新选择。

评价卡与风格档案有观察门槛；没有向量配置时继续使用人物和文本检索。长期记忆的数据存放在服务器的 MySQL／MinIO，U 盘搬运开发工作区不会自动复制远端数据库。服务器开发检查需要可用 Docker 和检查镜像，失败时拒绝应用生成修改。

本轮离线测试使用虚拟模型、临时数据库和 API 替身。前端构建与离线测试不能证明部署者自己的 QQ、模型提供商或新机器服务已经连通；首次上线仍需按[验收说明](../../qq-bot-py/docs/agent-upgrade.md#固定演示与观察)验证真实路径。

开发与 U 盘迁移步骤见[同一工作区开发说明](../../qq-bot-py/README.md)，表情规则见[表情说明](../../qq-bot-py/docs/meme_classification.md)。
