## 建议继续补充

优先补齐控制台与多角色特色，再补业务管理和其他交互。无需每个指令都单独截图。

| 建议文件名 | 内容 | 建议取景 |
| --- | --- | --- |
| `console-overview.png` | 控制台运行概览 | 第一张主图，显示导航、概览卡片和图表 |
| `personas-roster.png` | 人格管理和值班表 | 控制台页面与 QQ 值班图片可拼图 |
| `memes.png` | 表情库 | 展示筛选、分类和管理能力 |
| `memory-relations.png` | 群聊设置 / 记忆与关系 | 使用专门的演示数据 |
| `minigames-board.png` | 实际对局 / 文字游戏 | 开局后有落子的棋盘，或成语、猜数字的一轮过程 |
| `qq-vision.png` | 识图 | 用户发图与机器人的连贯回复 |
| `sign-in.png` | 签到与好感度 | 一次签到返回的图片与结果 |

控制台概览最适合作为后续首页第一张大图。人格和值班展示角色切换与当前只读日历；实际对局补足菜单图片无法展示的交互效果。COC 骰子、图片编辑和 Core 查询可按需要作为扩展示例补充，避免首页过长。

截图使用演示 QQ、演示群和演示聊天，不展示 Access Token、接口密钥、Cookie、真实用户记忆或私人关系。截取控制台时留出足够空间，不把浏览器地址栏中的敏感查询参数带进去。

提供后续图片后，在根 README 的「界面预览」对应功能下加入实际引用，例如：

```markdown
![控制台运行概览](docs/screenshots/console-overview.png)
```

README 只引用已存在的图片。头像单独保存在 `docs/assets/rinbot-avatar.png`。
